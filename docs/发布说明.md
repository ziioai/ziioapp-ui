# npm 发布准备

## 本地准备

- 仓库：https://github.com/ziioai/ziioapp-ui；作者 ziioai；MIT。
- 根包 private；`packages/ui`、`framework`、`vite-plugin-theme`、两个主题包和 `webapp-components` 各自拥有发布配置。发布前逐包核对版本与依赖。
- 安装：`pnpm install --frozen-lockfile`。
- 校验：`pnpm typecheck`、`pnpm upstream:check`。
- 打包：使用对应的根脚本 `pnpm pack:ui`、`pack:framework`、`pack:vite-plugin-theme`、`pack:theme-morandi`、`pack:theme-atmosphere` 或 `pack:webapp-components`；prepack 自动类型检查并构建，产物进入 `artifacts/`。
- 必须使用 pnpm pack：它将 publishConfig.exports 转换为 dist 入口，并展开 catalog。不要使用 npm pack 打包源码目录。
- 本地演练：`npm publish ./artifacts/ziioapp-webapp-components-0.1.0.tgz --dry-run --access public --registry=https://registry.npmjs.org/`。其他包替换为对应 tarball；dry-run 不发布。
- 在独立消费者中安装 tarball，检查 JS、类型、CSS 子路径。

## 正式发布时

- 当前不发布、不推送；无自动发布 workflow。
- 确认 npm 登录账号拥有 @ziioapp scope 的发布权限；GitHub 作者名不等于 npm scope 权限。
- 用 npm 官方 registry 核查目标版本未占用，确认 CHANGELOG 与最终版本。
- 经明确授权后，发布已验证的同一 tarball：`npm publish ./artifacts/<tarball>.tgz --access public --registry=https://registry.npmjs.org/`。
- 根据账户要求完成 2FA；不将 token 写入仓库。
- 发布后验证 npm 元数据与独立安装，再将消费方改为正式版本。
